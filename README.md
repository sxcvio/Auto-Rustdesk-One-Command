## ✨ Что это

Скрипт поднимает собственный сервер [RustDesk](https://github.com/rustdesk/rustdesk-server) (`hbbs` + `hbbr`) в Docker и дальше помогает его обслуживать. Подключения идут через **твой** сервер, а не через чужие. Это бесплатно, без лимитов и без регистрации.

| | |
|---|---|
| ⚡ **Одна команда** | Docker, конфиг, порты и запуск настраиваются сами |
| 🧭 **Удобное меню** | Установка, перенос, обновление, бэкап, логи |
| 🚚 **Перенос в 2 шага** | Скрипт сам находит RustDesk на старом сервере и забирает ключи |
| 🔐 **Свой ключ шифрования** | К серверу подключаются только твои клиенты |
| 🔄 **Автозапуск** | Сервер сам поднимается после перезагрузки |
| 🆓 **Полностью бесплатно** | Open-source сервер RustDesk, без подписок |

## 🚀 Установка

> Нужен сервер на **Ubuntu / Debian** и доступ под **root**.

Вставь в консоль:

```bash
curl -fsSL https://raw.githubusercontent.com/sxcvio/Auto-Rustdesk-One-Command/main/install-rustdesk.sh | bash
```

Откроется меню, выбери **1 — Установить сервер**. Скрипт спросит домен: если домена нет, просто нажми **Enter**, и будет использован IP сервера. Если домен есть, скрипт проверит, что он указывает на этот сервер.

В конце ты увидишь готовые данные для клиента:

```
  ╔═══════════════════════════════════════════════════════════════╗
  ║                 ✔  RustDesk сервер установлен                 ║
  ╠════════════════╦══════════════════════════════════════════════╣
  ║ Поле           ║ Значение                                     ║
  ╠════════════════╬══════════════════════════════════════════════╣
  ║ Сервер ID      ║ rd.example.com                               ║
  ║ Ретранслятор   ║ rd.example.com                               ║
  ║ Сервер API     ║ оставь пустым                                ║
  ║ Key            ║ AbCdEfGhIjKlMnOpQrStUvWxYz0123456789abcdefg= ║
  ╚════════════════╩══════════════════════════════════════════════╝
```

Данные также сохраняются в `~/rustdesk/client-info.txt`.

> 💡 Если на сервере уже стоит RustDesk (поставленный вручную или другим способом), скрипт его найдёт и предложит **сохранить старый ключ**, так что клиенты продолжат работать.

<details>
<summary><b>⚙️ Установка без вопросов (для автоматизации)</b></summary>

<br>

```bash

curl -fsSL https://raw.githubusercontent.com/sxcvio/Auto-Rustdesk-One-Command/main/install-rustdesk.sh | bash -s -- install rd.example.com

# с IP сервера
curl -fsSL https://raw.githubusercontent.com/sxcvio/Auto-Rustdesk-One-Command/main/install-rustdesk.sh | bash -s -- install
```

</details>

## 🧭 Меню

Та же команда открывает меню и после установки:

```
  ┌──────────────────────────────────────────────────┐
  │  ● Работает · rd.example.com                     │
  └──────────────────────────────────────────────────┘

   1  Установить сервер              новая установка
   2  Перенести с другого сервера    по SSH, с ключами
   3  Данные для подключения         сервер и ключ

   4  Обновить RustDesk              до последней версии
   5  Статус и логи                  проверка, перезапуск

   6  Сделать бэкап ключей           архив .tar.gz
   7  Восстановить из бэкапа
   8  Удалить сервер

   0  Выход
```

| Пункт | Что делает |
|---|---|
| **1** Установить | Ставит Docker и сервер, спрашивает домен, выводит данные для клиента |
| **2** Перенести | Забирает ключи со старого сервера по SSH и запускает сервер здесь |
| **3** Данные | Снова показывает таблицу с адресом и ключом |
| **4** Обновить | Скачивает свежую версию RustDesk, ключ и настройки сохраняются |
| **5** Статус | Проверяет контейнеры и порты, показывает логи, может перезапустить |
| **6** Бэкап | Сохраняет ключи (и базу устройств) в архив |
| **7** Восстановить | Поднимает сервер из архива с прежним ключом |
| **8** Удалить | Останавливает сервер, предлагает бэкап; папку с ключом удаляет только по явному подтверждению |

## 🌐 Порты

Если у хостера есть свой фаервол в панели, открой там:

| Порт | Протокол | Назначение |
|---|---|---|
| `21115` | TCP | Проверка типа NAT |
| `21116` | TCP + UDP | ID-сервер, пробивка NAT |
| `21117` | TCP | Ретранслятор (relay) |

`ufw` на самом сервере скрипт настраивает сам.

## 💻 Настройка клиента

Скачай клиент: [**Windows / macOS / Linux / Android**](https://github.com/rustdesk/rustdesk/releases/latest) · [**iPhone / iPad**](https://apps.apple.com/app/id1581225015)

Открой **Настройки → Сеть → ID/Ретранслятор** и заполни:

| Поле | Значение |
|---|---|
| **Сервер ID** | твой домен или IP |
| **Ретранслятор** | твой домен или IP |
| **Сервер API** | *оставь пустым* |
| **Key** | ключ из таблицы скрипта |

> 💡 **Совет:** настрой один клиент, нажми иконку «копировать» в окне ID/Ретранслятор и вставь строку на других устройствах кнопкой «вставить».

Если внизу клиента горит **🟢 Готово**, всё работает.

## 🚚 Перенос на другой сервер

### Как это устроено

Клиент RustDesk запоминает две вещи: **адрес сервера** и его **публичный ключ**. При подключении клиент проверяет, что сервер подписывается именно этим ключом. Если ключ другой, клиент откажется работать: это защита от подмены.

Ключ хранится на сервере в `~/rustdesk/data/` как пара файлов:

| Файл | Что это |
|---|---|
| `id_ed25519` | 🔒 приватный ключ, есть только на сервере |
| `id_ed25519.pub` | публичный ключ, тот самый **Key** из таблицы |
| `db_v2.sqlite3` | база зарегистрированных устройств (не обязательна, клиенты зарегистрируются сами) |

Новый сервер при установке создаёт **новую** пару ключей, и клиенты её не примут. Поэтому при переносе старую пару нужно перенести, тогда новый сервер для клиентов ничем не отличается от старого.

### Перенос через меню

**На новом сервере** запусти скрипт и выбери **2 — Перенести с другого сервера**:

1. Введи IP или домен **старого** сервера, пользователя и SSH-порт (Enter = `root` и `22`).
2. Введи пароль **от старого сервера**. Новый сервер сам подключится к старому по SSH.
3. Скрипт **сам найдёт RustDesk** на старом сервере (установленный этим скриптом, вручную через Docker или как systemd-сервис), покажет ключ и попросит подтвердить.
4. Ключи и база устройств копируются, проверяются и устанавливаются, потом сервер запускается.
5. Скрипт спросит домен. Введи **тот же**, что был у старого сервера.
6. Можно сразу остановить старый сервер, но лучше сделать это после смены DNS, чтобы клиенты не теряли связь.

Что останется сделать после переноса:

- **если в клиентах домен**, поменяй A-запись домена на IP нового сервера. В клиентах ничего менять не нужно, через несколько минут (пока обновится DNS) они подключатся сами;
- **если в клиентах IP**, впиши в клиентах новый IP. Ключ остаётся прежним.

> 💡 Поэтому лучше сразу использовать домен: при переезде меняется одна DNS-запись, а не настройки на каждом устройстве.

<details>
<summary><b>🔧 Перенос вручную (без меню)</b></summary>

<br>

Команда выполняется **на новом сервере**: он подключается к старому и забирает файлы. Читается как «откуда → куда».

```bash
# установи сервер на новой машине, затем:
scp root@СТАРЫЙ_IP:~/rustdesk/data/id_ed25519* ~/rustdesk/data/
cd ~/rustdesk && docker compose restart
cat ~/rustdesk/data/id_ed25519.pub   # должен совпасть со старым ключом
```

Можно и наоборот, **со старого сервера** отправить на новый:

```bash
scp ~/rustdesk/data/id_ed25519* root@НОВЫЙ_IP:~/rustdesk/data/
```

SSH на нестандартном порту: `scp -P 2222 ...`. Если между серверами нет доступа по паролю, скачай файлы к себе на ПК и залей на новый сервер.

</details>

## 💾 Бэкап и восстановление

**Пункт 6** сохраняет ключи в `~/rustdesk-backup-ДАТА.tar.gz`. Потом скрипт спросит, какая система на твоём компьютере (Windows / macOS / Linux) и куда сохранить архив (Загрузки, Документы, Рабочий стол или своя папка), и выдаст **готовую команду**. Её нужно вставить в терминал на компьютере:

```powershell
# пример для Windows → Загрузки (PowerShell)
scp root@203.0.113.10:/root/rustdesk-backup-20261103-162444.tar.gz "$env:USERPROFILE\Downloads\rustdesk-backup-20261103-162444.tar.gz"
```

Команда спросит пароль от сервера, после чего архив окажется в выбранной папке.

**Пункт 7** восстанавливает сервер из архива: ключ, базу устройств и адрес сервера (домен тоже сохраняется в бэкап). Залей архив на сервер (`scp rustdesk-backup-*.tar.gz root@сервер:~`), выбери пункт 7, и скрипт подставит последний найденный архив.

Скрипт также сам делает бэкап текущего ключа перед переносом, восстановлением и удалением, так что случайно потерять ключ не получится.

> ⚠️ В архиве лежит **приватный ключ** сервера. С ним можно выдать себя за твой сервер, поэтому никому его не передавай и не заливай в репозиторий.

## ❓ FAQ

<details>
<summary><b>Это платно?</b></summary>

<br>

Нет. Open-source сервер RustDesk бесплатный и без ограничений. Платная только отдельная версия **Server Pro** (веб-панель, логины, адресная книга), для обычных подключений она не нужна.

</details>

<details>
<summary><b>Клиент пишет «Не готово»</b></summary>

<br>

Почти всегда закрыты порты. Открой их в фаерволе хостера и проверь **пункт 5 — Статус и логи**. Проверить порт с другого компьютера:

```bash
nc -zv rd.example.com 21116
```

</details>

<details>
<summary><b>Что писать в «Сервер API»?</b></summary>

<br>

Ничего. Это поле нужно только для Server Pro. Предупреждение про HTTP можно игнорировать: трафик рабочего стола шифруется ключом.

</details>

<details>
<summary><b>Можно ли управлять айфоном?</b></summary>

<br>

Нет. iOS не позволяет сторонним приложениям управлять устройством. С айфона можно только подключаться к другим устройствам.

</details>

<details>
<summary><b>Домен на Cloudflare</b></summary>

<br>

Выключи проксирование для записи (серое облако, **DNS only**). Порты RustDesk через прокси Cloudflare не работают.

</details>

<details>
<summary><b>При переносе скрипт не нашёл RustDesk на старом сервере</b></summary>

<br>

Скрипт ищет ключи в контейнере `hbbs` и в типичных папках (`~/rustdesk/data`, `/opt/rustdesk`, `/var/lib/rustdesk-server` и других). Если твои ключи лежат в другом месте, скопируй файлы `id_ed25519` и `id_ed25519.pub` вручную (см. «Перенос вручную»). Подключайся к старому серверу под `root`: обычному пользователю файлы ключей могут быть недоступны.

</details>

<details>
<summary><b>Повторный запуск установки что-то сломает?</b></summary>

<br>

Нет. Ключ сохраняется, адрес подставляется прошлый, клиенты продолжают работать. Так можно, например, сменить домен.

</details>

<details>
<summary><b>Команды Docker вручную</b></summary>

<br>

```bash
cd ~/rustdesk
docker compose logs -f     # логи
docker compose restart     # перезапуск
docker compose down        # остановить
docker compose up -d       # запустить
```

</details>
